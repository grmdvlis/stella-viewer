# 밤결 · 나의 작은 우주

스마트폰의 위치·방위·기울기와 시각을 기반으로 별자리를 탐색하는 정적 웹앱. 프레임워크 및 패키지 설치 없이 GitHub → Vercel로 배포할 수 있습니다.

## 현재 배포본: PC·모바일 통합

최신 iPhone 배포본과 동일한 화면·센서 코드를 기준으로 하나의 소스를 사용합니다. 같은 Vercel 주소에서 PC는 드래그·방향키와 FOV 70°, 스마트폰은 센서·터치와 FOV 60°를 사용합니다. 화면 폭 650px 이하 또는 주 입력 장치가 터치인 경우 모바일 표시를 선택합니다. 모바일 레이아웃은 CSS 화면 폭에 맞춰 적용되며, PC에서도 창을 좁히면 좁은 화면에 맞춰집니다.

앞으로 사용할 파일은 **outputs/bamgyeol.zip** 하나입니다. 압축을 풀면 **bamgyeol** 폴더가 나옵니다. 이 폴더 **안의 전체 파일과 하위 폴더**를 GitHub의 기존 앱 파일이 있는 위치에 덮어 올리세요. 기존 GitHub 배포 폴더 이름은 변경하지 않아도 됩니다. Vercel 프로젝트 및 주소도 유지합니다. 기존 PC/iPhone 출력물은 work/outputs-archive에 보관합니다.

업데이트 후 `python tools/package_outputs.py`를 실행하면 통합 ZIP과 압축 해제 폴더가 갱신됩니다. 아래 0.2~0.4 변경 기록에 등장하는 PC/iPhone 별도 ZIP 이름은 이전 배포 방식입니다.

## 0.5 뷰어 표시와 모바일 위치 설정

기본 모드에서 GPS를 얻기 전이나 실패한 경우 서울 좌표로 미리보기하며 주황색 표시등과 '미리보기 - 서울'을 표시합니다. 팝업 맨 위에 위치 권한 안내를 주황색으로 표시합니다. GPS 성공 후에는 녹색 표시등과 '현위치'를 표시합니다. 팝업은 지역명, 위도, 경도, 닫기 안내 순서이며 좌표 글씨는 닫기 안내보다 큽니다. 팝업 폭은 모바일 162px (기존 270px의 60%), PC 320px (기존보다 50px 증가)입니다.

현재 시각 앞의 '현재 ·'를 제거했습니다. 사용자가 지정한 시각에는 '지정 ·'를 유지합니다. 지정 모드 위치 입력창은 좁은 화면에서도 입력칸과 버튼이 잘리지 않게 제한합니다. 지정 모드에서는 센서 버튼을 숨기고 시간 설정 버튼을 오른쪽 아래에 배치합니다.

안내 문구는 두 모드 모두 최근 **3초**의 보정된 3축 회전 이동량을 합산합니다. 누적 이동이 **2° 미만**이면 나타나고, **10° 이상**이면 즉시 페이드아웃을 시작합니다. 나타나는 전환은 0.55초, 사라지는 전환은 1.6초입니다. 앞뒤로 흔든 이동도 합산하며, 0.15° 미만의 미세 잡음은 누적 기준 자세를 유지해 억제합니다. 드래그·방향키에도 같은 기준을 적용합니다. 진입 및 탭 복귀 시에는 새 3초 관측 창으로 시작합니다. 수정 위치: orientation.js의 ViewHint, style.css의 hint 전환 시간. 이전 0.4 안내 문구 기준을 대체합니다.

## 실행 / 배포

Node.js 20 이상에서 `npm run dev` 후 http://127.0.0.1:5173 을 엽니다. `npm test`는 좌표 변환·투영·데이터 수를 검증합니다. `npm run build`는 배포용 dist를 만듭니다.

이 폴더의 내용을 GitHub 저장소에 올리고 Vercel에서 Import Project를 선택합니다. Framework는 Other, Build Command는 `npm run build`, Output Directory는 `dist`입니다. vercel.json에 동일 설정이 들어 있습니다. 실제 GitHub 저장소 생성이나 Vercel 배포는 이 작업에서 실행하지 않았습니다.

## 실기기 확인할 사항

HTTPS 최상위 페이지에서 테스트해야 위치·카메라·센서 권한이 정상 작동합니다. iOS의 센서 권한은 버튼 클릭으로 요청해야 합니다. 기기/브라우저별 방위 정확도와 지원이 달라 iOS Safari 및 Android Chrome에서 후면 카메라 방향, 기울기, 방위 보정을 실제 별과 비교해야 합니다. 센서는 권한을 켠 뒤에도 데이터가 없을 수 있습니다. 이 작업에서는 실기기 테스트를 하지 않았습니다.

상대 방위만 제공하는 기기는 센서 방향으로 하늘을 제어하지 않습니다. 금속·자석·기기 캘리브레이션에 영향을 받습니다. 항성에는 대기 굴절·세차/장동·고유운동·지형·광공해·심우주 천체를 현재 반영하지 않습니다. 행성 위치는 Astronomy Engine으로 계산하며 관측자 시차·광행 시간·광행차·세차/장동을 반영합니다. 별/행성 위치는 1분 단위로 캐시하여 센서 이동에 따른 재계산을 줄입니다. 별 좌표는 J2000 카탈로그 기준이므로 정밀 관측 도구가 아닙니다. 거리와 겉보기 밝기는 단순 비례하지 않아 크기는 겉보기 등급을 사용합니다.

도장·프로필은 계정 서버로 동기화되지 않습니다. 브라우저 데이터 삭제 시 잃을 수 있으므로 내려받아 보관하세요. 다중 사용자 소원 게시판은 후속 개발 대상으로 DB·인증·게시물 정책 구현이 필요합니다.

센서 화면은 휴대폰의 오른쪽·위쪽·후면 카메라 방향을 포함한 3차원 회전 기저를 사용합니다. 천정/천저를 넘어갈 때 방위각만으로 화면의 위쪽을 재구성하지 않으므로 180° 뒤집힘을 방지합니다. 드래그/방향키의 고도 제한도 제거했습니다. 센서 보정 정확도와 iOS 실기기의 천정 통과 동작은 기기에서 다시 확인해야 합니다.

태양/달 이미지는 구별용 일러스트이며 달 위상은 이미지에 반영하지 않습니다. 지평선 방위 글자는 14px 굵은 글씨입니다. SkyView Lite의 기기를 움직여 천체를 식별하는 흐름을 참고했습니다: https://apps.apple.com/us/app/skyview-lite/id413936865 . 실제 앱을 실행해 UI 전체를 재현한 것은 아닙니다.

## 0.4 센서 안정화 / 위치 팝업

iOS 나침반의 `webkitCompassHeading + alpha`는 센서 연결 때 한 번만 북쪽 보정 기준으로 잡습니다. 이후 기울기에 따라 바뀌는 나침반 값을 매 화면에 적용하지 않습니다. Android는 북쪽 기준의 absolute orientation을 우선 사용하며 두 이벤트가 중복되면 absolute 이벤트만 반영합니다. 위치/센서 버튼을 다시 누르면 보정 기준을 다시 잡습니다.

`alpha`, `beta`, `gamma` 전체 회전을 쿼터니언으로 변환해 가장 짧은 경로로 보간합니다. 미세 변화 0.15° 이하를 억제하고, 고도 ±30° 이내에서는 더 강하게 평활화합니다. 큰 움직임은 빠르게 따라가도록 보간 강도를 줄이며, 한 번만 튀는 큰 신호는 확인 후 반영합니다. 시간 기준 보간이므로 센서 이벤트 빈도에 의존하지 않습니다. 실제 iPhone/Galaxy 센서의 체감은 실기기에서 재검증해야 합니다.

하단 안내 문구는 **화면에 최종 적용된 회전**이 기준 자세에서 누적 1.5° 이상 바뀌면 1.6초 동안 사라집니다. 센서 모드의 원본은 DeviceOrientationEvent의 alpha/beta/gamma이며, 보정·평활화 후의 3축 회전 각도를 비교하므로 기기 회전(roll)도 포함합니다. 드래그/방향키에도 동일 기준을 적용합니다. 20초 동안 기준 이상의 움직임이 없으면 0.55초 동안 나타나고, 다른 탭에서 뷰어로 돌아오면 즉시 나타납니다. 조정 위치: orientation.js의 ViewHint (1.5°, 20000ms), style.css의 hint 전환 시간.

현위치 버튼 아래에 위·경도 3자리, 도시명 팝업이 열립니다. GPS 미허용 초기 화면은 서울 미리보기임을 팝업에서 표시합니다. 국내 도시명은 기기 내 행정구역 경계 조회이며 좌표를 외부 도시 조회 서비스에 전송하지 않습니다. 출처: 통계청 통계지리정보서비스 제공 2013 경계, southkorea/southkorea-maps 변환본. 경계 변경·단순화 때문에 도시명은 참고용이며 해외는 일부 프리셋 외에 확인 불가로 표시합니다. 세부 출처와 사용 조건은 data/korea-cities-README.txt 참조.

`python tools/package_outputs.py`는 ZIP 두 개와 압축 해제된 업로드 폴더를 함께 갱신합니다. 기존 업로드 폴더는 work/outputs-archive에 보관합니다. GitHub에는 **bamgyeol-pc 폴더 안의 전체 파일**을 같은 위치에 덮어 올려야 합니다. index.html 단독 업로드로는 수정 JS/CSS가 적용되지 않습니다.
